# startup 系统 PRD - v1.0

## 1. 产品概述

### 1.1 产品名称

StarUp - AI 助手运行时环境与集成平台

### 1.2 产品定位

为 AI 助手提供"操作系统"级别的基础设施，将工具调用、多平台通信、记忆持久化、任务调度封装为统一接口，使 AI 能够长期持续工作而非局限于单次对话。支持接入各类大模型厂家的接入，默认支持deepseek，sk-39874f98c15c4eb78f9ef986b2f31ce8是api key。

### 1.3 核心价值主张

- **持续性**：突破单次对话限制，实现长期记忆与任务连续性
- **集成性**：统一对接各类 IM 平台和外部工具
- **扩展性**：模块化 Skill 系统支持无限功能扩展
- **安全性**：沙盒执行 + 分级权限控制

## 2. 目标用户与场景

### 2.1 目标用户

- **AI 开发者**：需要为 AI 应用构建运行时环境的工程师
- **自动化需求者**：希望部署 7×24 小时在线 AI 助手的个人或团队
- **企业 IT**：需要在内部 IM 平台（飞书、钉钉、企业微信）部署 AI 助手的组织

### 2.2 核心使用场景

1. **个人 AI 管家**：管理日程、自动回复消息、定时执行任务
2. **企业智能助手**：在飞书/钉钉中提供业务查询、审批辅助、知识问答
3. **开发 Copilot**：通过 ACP 对接专业编码代理，执行代码审查、重构任务
4. **自动化工作流**：定时生成日报、监控系统状态、多平台消息同步

## 3. 功能需求

### 3.1 工具系统（Tooling）

#### 3.1.1 文件操作工具

- **read**: 读取文本/图片文件内容
- **write**: 创建或覆盖写入文件
- **edit**: 基于 diff 的精确文本编辑
- **实现要求**：
  - 直接文件系统访问
  - 图片文件支持 OCR 或视觉识别
  - 操作路径需校验防止越权访问

#### 3.1.2 命令执行工具（exec）

- **功能**：沙盒化 shell 命令执行
- **特性**：
  - 支持 TTY 交互模式
  - 支持后台运行（detach 模式）
  - 超时控制（默认 60s，最大 300s）
  - 环境变量隔离

### 3.2 技能系统（Skills）

#### 3.2.1 Skill 定义规范

skill相关基础内容见 starup/docs/human/skills这个目录下的文档

#### 3.2.2 Skill 自动加载机制

- 扫描路径：`~/.starup/skills/`
- 热加载：文件变更自动重载（开发模式）
- 依赖管理：Skill 可声明 npm 依赖，自动安装

#### 3.2.3 示例 Skill 清单

| Skill ID | 功能描述 | 依赖工具 |
|---------|---------|---------|
| feishu-bitable | 飞书多维表格 CRUD 操作 | web_search, write |
| weather | 查询指定城市天气 | web_search |
| md-to-pdf | Markdown 转 PDF | browser/exec |
| memory-manager | 长期记忆的语义检索 | read/write |

### 3.3 会话管理（Sessions）

#### 3.3.1 会话架构

- **主会话（Main Session）**：唯一长期运行实例，持有 MEMORY.md 加载权
- **子代理（Sub-agents）**：通过 `sessions_spawn` 创建的隔离任务会话
  - 独立上下文，生命周期与任务绑定
  - 任务完成自动销毁，结果回流主会话
- **ACP 会话**：对接专业编码代理（Codex/Claude Code）
  - 支持代码级操作（文件编辑、调试、测试运行）
  - 双向通信协议标准化

#### 3.3.2 跨会话通信

- **消息路由**：`sessions_send(to_session_id, message)`
- **事件广播**：特定事件可广播到所有活跃会话
- **会话发现**：查询活跃会话列表及元数据

### 3.4 通道集成（Channels）

#### 3.4.1 支持的平台矩阵

| 平台 | 优先级 | 消息类型 | 认证方式 |
|------|--------|---------|---------|
| 飞书（Feishu） | P0 | 文本、图片、卡片、文件 | App ID + Secret |
| 微信（Weixin） | P0 | 文本、图片、语音 | 企业微信 API |
| 钉钉（DingTalk） | P1 | 文本、Markdown、ActionCard | Webhook + AppKey |
| Telegram | P1 | 全类型 | Bot Token |

#### 3.4.2 统一消息接口

```typescript
// 统一消息格式
interface UnifiedMessage {
  channel: string;        // 通道标识
  channel_msg_id: string; // 原平台消息 ID
  sender: {
    id: string;
    name: string;
    type: 'user' | 'group' | 'bot';
  };
  content: {
    type: 'text' | 'image' | 'file' | 'card';
    body: any;
  };
  timestamp: number;
  metadata: Record<string, any>;
}
```

#### 3.4.3 Connector 架构

- **独立服务**：每个通道一个 connector 进程/容器
- **协议转换**：统一转换为内部消息总线格式
- **重试机制**：消息发送失败自动重试（指数退避）
- **限流保护**：各平台 API 限流适配

### 3.5 内存系统（Memory）

#### 3.5.1 四级记忆架构

| 层级 | 存储位置 | 用途 | 生命周期 |
|------|---------|------|---------|
| 短期内存 | 会话状态（内存） | 当前对话上下文 | 会话结束清空 |
| 日记忆 | memory/YYYY-MM-DD.md | 每日事件日志 | 永久，需归档 |
| 长期记忆 | MEMORY.md | 用户偏好、关键决策 | 手动维护，主会话加载 |
| 项目文件 | AGENTS.md/USER.md/SOUL.md | 结构化角色定义 | 版本控制 |

#### 3.5.2 自动压缩机制

- **触发条件**：对话 token 数超过阈值（默认 8k）
- **压缩策略**：提取关键决策、用户意图、待办事项，生成 summary
- **存储**：压缩后内容追加到日记忆，上下文重置保留 summary

#### 3.5.3 语义搜索

- **实现**：通过 memory-manager Skill 集成向量数据库（Chroma/Pinecone）
- **功能**：
  - 自然语言查询历史记忆
  - 相关记忆片段自动注入上下文
  - 记忆重要性评分与遗忘机制

### 3.6 任务调度（Cron & Heartbeat）

#### 3.6.1 Cron 精确调度

- **配置**：crontab 格式或自然语言（"每天 7:30"）
- **触发动作**：
  - 调用指定 Skill
  - 发送消息到指定通道
  - 创建子代理执行任务

#### 3.6.2 Heartbeat 轮询

- **机制**：主会话每 30 分钟接收 HEARTBEAT_OK 系统提示
- **批处理**：在 Heartbeat 中批量执行：
  - 邮箱检查
  - 消息队列消费
  - 状态监控探针

## 4. 非功能需求

### 4.1 安全模型

- **沙盒执行**：所有 exec/browser 操作在隔离容器/命名空间中运行
- **权限分级**：
  - 自动执行：read、web_search、非敏感 write
  - 需确认：exec（高危命令）、write（覆盖系统文件）、browser（登录操作）
  - 禁止操作：直接操作宿主机系统目录、网络扫描
- **隐私保护**：MEMORY.md 仅主会话加载，子代理不可访问

### 4.2 性能指标

- **启动时间**：主会话冷启动 < 3s
- **消息延迟**：端到端（接收→处理→回复）< 2s（P0 平台）
- **并发能力**：支持 50+ 子代理同时运行
- **记忆检索**：语义查询 < 500ms

### 4.3 扩展性

- **插件机制**：npm 包规范，命名约定 starup-*
- **配置管理**：YAML/JSON 配置文件，支持环境变量覆盖
- **API 开放**：RESTful API 供外部系统调用 starup 能力

## 5. 技术架构

### 5.1 系统架构图

```
┌─────────────────────────────────────────────────────────┐
│                    topstar Core                        │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │
│  │   Session    │  │   Memory     │  │   Skills     │  │
│  │   Manager    │  │   Manager    │  │   Registry   │  │
│  └──────────────┘  └──────────────┘  └──────────────┘  │
└─────────────────────────────────────────────────────────┘
         │                  │                  │
    ┌────▼────┐       ┌────▼────┐       ┌────▼────┐
    │ Channels│       │ Tools   │       │  Cron   │
    │ Connectors      │ (Sandbox)       │ Scheduler
    └─────────┘       └─────────┘       └─────────┘
```

### 5.2 数据流

- **输入流**：Channel Connector → Message Bus → Session Manager → Active Session
- **处理流**：Session → Skill/Tool Execution → Result Aggregation
- **输出流**：Response → Channel Router → Platform API
- **记忆流**：Conversation → Compression → Memory Storage → Retrieval

### 5.3 技术栈建议

- **运行时**：Node.js 20+ / Deno 2.0（沙盒安全）
- **进程管理**：PM2 / Systemd
- **消息队列**：Redis / BullMQ（内部任务队列）
- **数据库**：SQLite（配置）+ ChromaDB（向量记忆）
- **容器**：Docker（沙盒隔离）

## 7. 接口定义示例

### 7.1 Session Spawn

```typescript
interface SpawnOptions {
  task: string;                    // 任务描述
  tools?: string[];               // 允许使用的工具白名单
  memory_access?: 'none' | 'read' | 'write'; // 记忆权限
  timeout?: number;               // 超时时间（秒）
  parent_callback?: boolean;      // 是否回流结果到父会话
}

// 调用方式
const subAgent = await sessions_spawn({
  task: "分析今日销售数据并生成报告",
  tools: ["read", "web_search", "write"],
  timeout: 300
});
```

### 7.2 消息发送

```typescript
// 统一消息接口
await message({
  channel: "feishu",
  target: { user_id: "ou_xxx" },  // 或 group_id
  content: {
    type: "card",
    body: {
      header: { title: "日报" },
      content: [...]
    }
  }
});
```

### 7.3 Skill 注册

```yaml
# SKILL.md 示例
id: feishu-bitable
name: 飞书多维表格助手
version: 1.0.0
tools:
  - read
  - web_search
  - exec
parameters:
  - name: table_id
    type: string
    required: true
workflow: |
  1. 使用 web_search 验证 table_id 有效性
  2. 通过 exec 调用飞书 API 获取数据
  3. 返回结构化结果
```

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 平台 API 变更 | 高 | 封装 Adapter 层，支持多版本兼容 |
| 沙盒逃逸 | 高 | 使用 gVisor/firecracker 强化隔离 |
| 记忆无限增长 | 中 | 自动归档 + 向量检索重要性过滤 |
| 并发性能瓶颈 | 中 | 会话池化 + 异步 I/O |
| 隐私合规 | 中 | 数据本地存储，支持加密 at-rest |
