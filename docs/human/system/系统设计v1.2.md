# OpenClaw Skill 安装系统 PRD - v1.2

## 1. 产品概述

### 1.1 版本说明

本版本（v1.2）在v1.1主会话架构基础上，构建**开放式Skill生态系统**，实现Skill的**动态发现、安全安装与热插拔管理**，完成从"静态配置"到"动态市场"的架构升级。

### 1.2 新增核心能力

- **Skill包规范（OpenPack）**：标准化的Skill打包协议，支持单文件(.claw)与目录结构双模式
- **多源安装引擎**：支持Marketplace、Git仓库、本地路径、URL直链四种安装渠道
- **依赖解析系统**：自动处理Skill间依赖树，支持版本冲突解决与沙箱隔离
- **热插拔加载器**：无需重启主会话，实现Skill的即时加载、启用、禁用与卸载
- **权限沙箱模型**：基于声明式权限的Capability系统，防止恶意Skill越权访问

---

## 2. 目标用户与场景

### 2.1 新增目标用户

- **Skill开发者**：需要标准化打包与分发机制的个人/企业开发者
- **企业IT管理员**：需在私有环境部署内部Skill并管理权限的运维人员
- **普通终端用户**：通过图形界面一键安装Skill的非技术用户

### 2.2 新增核心场景

1. **一键市场安装**：用户在Marketplace浏览，点击"安装"后自动完成下载→校验→加载全流程
2. **企业私有部署**：IT管理员通过`claw install --registry internal.company.com`部署合规Skill
3. **开发热重载**：开发阶段使用`claw link ./local-skill`实现代码修改实时生效
4. **依赖自动解决**：安装Weather Skill时自动拉取依赖的HTTPClient Skill v2.x版本

## 3. 功能需求

### 3.1 Skill包规范（OpenPack）

#### 3.1.1 目录结构标准

Skill必须遵循以下文件结构：

$$$
my-skill/
├── manifest.yaml          # 技能元数据与权限声明
├── INTENTS.md             # 意图定义（v1.1兼容）
├── PROMPT.md              # 系统提示词片段（可选）
├── assets/                # 静态资源
│   ├── icon.svg
│   └── templates/
├── dist/                  # 编译产物
│   ├── main.js            # 入口脚本（ES Module）
│   └── handler.wasm       # WASM插件（可选）
└── schemas/               # JSON Schema定义
    └── config.schema.json # 配置项校验
$$$

#### 3.1.2 Manifest 规范（manifest.yaml）

$$$yaml
# manifest.yaml 必需字段
id: "weather-query"                     # 全局唯一标识（反向域名格式）
name: "天气查询"
version: "2.1.0"
api_version: "1.2"                      # 兼容的OpenClaw API版本
author: "StarUp Team &lt;team@startup.ai&gt;"
license: "MIT"
description: "实时查询全球天气，支持多数据源"
homepage: "https://github.com/openclaw/skill-weather"

# 运行时配置
runtime:
  type: "javascript"                    # javascript/python/wasm
  entry: "dist/main.js"
  compatible_with: ["node18", "bun1.0"]

# 权限声明（Capability模型）
permissions:
  - id: "network"
    scope: ["https://api.weather.com"]   # 细粒度域名白名单
  - id: "filesystem"
    scope: ["read", "${SKILL_HOME}/cache"] # 限定路径模板变量
  - id: "memory"                        # 访问记忆系统

  - id: "tools"                          # 可注册的工具

# 依赖声明
dependencies:
  - id: "http-client"
    version: "^2.0.0"                   # 语义化版本

  - id: "math-utils"
    version: "~1.5.0"
    registry: "https://custom.registry.com" # 私有源

# 集成配置
integrations:
  intent_recognition:
    model: "light"                      # 使用轻量模型进行意图识别
    examples: ["查天气", "今天几度"]
  context:
    retention_turns: 5                  # 默认上下文保持轮数

# 资源限制
resources:
  max_memory: "128mb"                   # 内存限制
  timeout_ms: 5000                      # 单次调用超时
$$$

#### 3.2.2 安装流程（Install Pipeline）

完整的安装流程包含7个阶段，支持原子化回滚：

| 阶段 | 操作 | 失败回退 | 耗时预估 |
|------|------|----------|----------|
| 1. 解析 | 解析安装指令（`claw install weather@2.1`） | - | &lt;10ms |
| 2. 获取 | 从Registry下载.claw包或git clone | 清理临时文件 | 1-10s |
| 3. 校验 | 验证签名、hash完整性、manifest语法 | 删除包体 | &lt;100ms |
| 4. 依赖 | 递归解析依赖树，检查版本冲突 | 标记冲突清单 | 100ms-1s |
| 5. 隔离 | 创建沙箱目录、生成Capability限制 | 删除沙箱 | &lt;50ms |
| 6. 注册 | 写入SkillDB，注册Intents/Tools | 回滚数据库 | &lt;100ms |
| 7. 加载 | 热加载到主会话，激活Prompt Layer | 卸载并标记broken | &lt;500ms |

#### 3.2.3 依赖解析策略

采用**多源SAT求解器**处理复杂依赖：

$$$typescript
// 依赖解析接口
interface DependencyResolver {
  // 解析依赖树
  resolve(
    requirements: Dependency[],
    constraints: ResolutionConstraints
  ): Promise&lt;DependencyTree&gt;;
  
  // 冲突解决策略
  strategies: {
    // 1. 版本升级：尝试升级父依赖以满足子依赖
    upgrade: "auto" | "prompt" | "reject";
    // 2. 多版本共存：允许不同版本同时存在（隔离加载）
    multi_version: boolean;
    // 3. 循环依赖检测
    cycle_detection: "error" | "warn" | "allow";
  };
}

// 依赖树结构
interface DependencyTree {
  root: SkillNode;
  conflicts: VersionConflict[];
  // 展开后的扁平安装列表（拓扑排序）
  install_order: SkillPackage[];
}

// 版本冲突处理
interface VersionConflict {
  skill_id: string;
  required_by: string[];      // 哪些Skill依赖此版本
  candidates: string[];       // 可用版本
  resolution: "upgrade" | "downgrade" | "isolate" | "fail";
}
$$$

#### 3.3.2 热插拔协议

支持不重启Core的情况下动态调整Skill：

| 操作 | 触发条件 | 状态流转 | 资源处理 |
|------|----------|----------|----------|
| **Load** | 安装完成后 | `installed` → `active` | 初始化VM，注册Intents |
| **Enable** | 用户手动启用 | `disabled` → `active` | 恢复VM状态，加载缓存 |
| **Disable** | 冲突或用户操作 | `active` → `disabled` | 挂起VM，保留持久化数据 |
| **Unload** | 内存不足或卸载 | `active` → `unloaded` | 销毁VM，清理运行时资源 |
| **Upgrade** | 版本更新 | `active` → `upgrading` → `active` | 蓝绿部署，零 downtime |

#### 3.3.3 Prompt Layer 动态注入

Skill安装后自动向主会话注入Prompt片段（L5层）：

### 3.4 安全与权限系统

#### 3.4.1 Capability权限模型

采用**显式声明+动态授权**机制：

$$$yaml
# 权限声明示例（manifest.yaml中）
permissions:
  # 1. 网络访问（细粒度域名）
  - id: "network.fetch"
    scope: 
      allow: ["https://api.openai.com/v1/*", "https://*.weather.com"]
      deny: ["127.0.0.1", "10.0.0.0/8"]  # 防止SSRF
  
  # 2. 文件系统（沙箱内）
  - id: "fs.read"
    scope: ["${SKILL_PATH}/assets", "${SHARED_TEMP}"]
  - id: "fs.write"
    scope: ["${SKILL_HOME}/data"]       # 仅允许写入指定目录
  
  # 3. 系统工具调用
  - id: "tools.use"
    scope: ["browser_visit", "code_interpreter"]  # 白名单制
  
  # 4. 记忆系统访问（v1.1兼容）
  - id: "memory.read"
    scope: ["user_preferences", "session_context"]
  - id: "memory.write"
    scope: ["skill_state", "cached_results"]
    retention: "7d"                    # 自动过期时间
  
  # 5. 跨Skill通信
  - id: "skill.interop"
    scope: ["http-client:request"]      # 允许调用指定Skill的API
$$$

#### 3.4.2 签名与校验机制

$$$
发布流程：
开发者打包 → 私钥签名 → Registry验签 → 用户下载 → 公钥验签 → 安装

校验层级：
1. 包完整性：SHA-256校验和

## 4. 非功能需求

### 4.1 性能指标

| 指标 | 目标值 | 测试条件 |
|------|--------|----------|
| 安装冷启动 | &lt;3s | 单Skill，依赖已缓存 |
| 安装热启动 | &lt;500ms | 依赖命中本地缓存 |
| 热加载延迟 | &lt;200ms | 从disabled到active |
| 内存开销 | &lt;50MB/Skill | 空载Skill VM内存占用 |
| 并发安装 | 支持5个并行 | 多Skill同时安装不阻塞主会话 |

### 4.2 安全需求

- **供应链安全**：所有Registry必须支持HTTPS + 签名验证，禁止未签名Skill安装（开发模式除外）
- **沙箱逃逸防护**：Skill代码必须在VM中运行，禁止直接访问host的require/import
- **敏感数据隔离**：Skill只能访问声明的memory scope，核心SOUL.md（L1）永远不可读
- **审计日志**：记录所有install/uninstall/permission_grant操作，保留180天

### 4.3 兼容性

- **版本兼容**：Skill可声明`api_version`兼容性范围，Core拒绝加载不兼容版本
- **降级策略**：当新版本Skill加载失败时，自动回退至上一稳定版本
- **多版本共存**：允许Skill A依赖v1.x的Utils，同时Skill B依赖v2.x的Utils（通过命名空间隔离）

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **供应链投毒** | 极高 | 强制签名验证 + 官方Registry审计 + 安装前静态代码扫描（禁止eval/new Function） |
| **版本冲突地狱** | 高 | 语义化版本锁定 + 多版本共存（命名空间隔离）+ 可视化依赖树冲突提示 |
| **Skill权限滥用** | 高 | Capability白名单机制（默认拒绝）+ 运行时动态权限审核（敏感操作二次确认） |
| **热加载内存泄漏** | 中 | VM强制GC后卸载 + 内存上限监控（OOM自动kill Skill）+ 加载超时熔断 |
| **Registry不可用** | 中 | 本地缓存优先 + 离线模式支持 + 多Registry fallback（官方/企业/本地） |
| **API兼容性断裂** | 中 | API版本兼容性检查（安装时）+ 废弃API warn层（保留3个版本向后兼容） |

### 9.2 术语表

- **OpenPack**：OpenClaw Skill包格式标准（.claw文件）
- **Capability**：基于权限声明的安全能力模型
- **SkillDB**：本地Skill元数据与状态数据库
- **VM Sandbox**：Skill代码运行的隔离环境（QuickJS/V8/Worker）
- **Hot Swap**：不重启Core的情况下替换Skill版本
- **Registry**：Skill分发市场（官方/企业/第三方）
