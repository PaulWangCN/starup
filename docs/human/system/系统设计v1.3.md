# StarUp Skill 自举与元管理 PRD - v1.3

## 1. 产品概述

### 1.1 版本说明

本版本（v1.3）在v1.2开放式Skill生态基础上，实现**自举式架构（Bootstrapping Architecture）**与**元Skill管理（Meta-Skill Management）**。通过内置核心 Meta-Skill，系统将 Skill 安装、更新、卸载等管理能力本身也封装为可扩展的 Skill，实现"用 Skill 管理 Skill"的递归设计。

### 1.2 新增核心能力

- **意图驱动的 Skill 管理**：自然语言触发安装（"帮我安装天气查询功能"），系统自动识别意图并调用 `core.installer` 执行
- **Meta-Skill 架构**：内置 `core.installer`、`core.registry`、`core.updater` 三个元 Skill，作为系统管理入口
- **SkillHub 集成**：标准化搜索协议支持官方 Hub、企业私有 Hub、本地目录三种源
- **声明式安装协议**：通过 `InstallIntent` 描述安装需求，支持模糊匹配与智能推荐
- **零重启热扩展**：Skill 安装完成后立即注入主会话 Prompt Layer（L5），无需重启 Core

---

## 2. 目标用户与场景

### 2.1 新增目标用户

- **系统运维人员**：通过自然语言或 CLI 远程管理 Agent 能力，无需手动编辑配置文件
- **企业部署管理员**：批量推送合规 Skill 到内网环境，通过元 Skill 审计已安装组件
- **AI 训练师**：为特定业务场景快速装配 Skill 组合，测试后一键卸载

### 2.2 新增核心场景

1. **对话式安装**：用户说"我需要能查邮件的功能" → Agent 识别意图 → 搜索 "email" → 展示候选 → 确认后自动下载安装
2. **依赖自举安装**：安装 Weather Skill 时自动发现需要 Location Skill → 递归调用 installer 完成依赖链安装
3. **离线环境部署**：管理员预先下载 `.startup` 包，通过 `core.installer` 本地加载，绕过公网 Hub
4. **Skill 组合快照**：保存当前已安装 Skill 集合为 Profile，新环境一键还原（Infrastructure as Skill）

## 3. 功能需求

### 3.1 意图识别增强（Skill 管理意图）

#### 3.1.1 扩展意图分类表

在v1.1网关层意图基础上，增加 `skill_management` 大类：

| 意图ID | 置信度阈值 | 路由目标 | 示例触发语料 | 槽位提取 |
|--------|------------|----------|--------------|----------|
| `skill.install` | 0.75 | core.installer | "安装天气 skill"、"添加邮件功能" | `skill_name`, `source`, `version` |
| `skill.uninstall` | 0.80 | core.installer | "卸载天气"、"删除这个插件" | `skill_id`, `purge_data` |
| `skill.update` | 0.75 | core.updater | "更新所有技能"、"升级到最新版" | `skill_id`, `force` |
| `skill.query` | 0.70 | core.registry | "列出已安装技能"、"有什么功能" | `filter`, `verbose` |
| `skill.search` | 0.70 | core.registry | "找一下翻译相关的 skill"、"搜索日历" | `keyword`, `source` |
| `skill.config` | 0.80 | target skill | "配置天气 skill 的默认城市" | `skill_id`, `config_key`, `config_value` |

#### 3.1.2 模糊匹配与消歧

当用户输入模糊时，由 `core.installer` 触发确认流程：

$$$
用户: "我要安装天气"
↓
IntentRouter: 识别为 skill.install (置信度 0.85)
↓
core.installer 执行槽位填充：
  - skill_name: "天气" (模糊)
  - 调用 SkillHub.search("天气")
↓
返回候选列表：
  1. weather-query (官方，支持全球)
  2. weather-china (精简，仅国内)
  3. weather-pro (付费，含历史数据)
↓
Agent 向用户确认："找到以下天气相关功能，请确认安装哪一个？"
↓
用户选择 → 继续安装流程
$$$

### 3.2 内置 Meta-Skill 系统

#### 3.2.1 Meta-Skill 定义

v1.3 内置三个核心 Meta-Skill，位于 `~/.startup/core/` 目录，具备**系统级 Capability**：

| Meta-Skill | ID | 职责 | 特殊权限 |
|------------|-----|------|----------|
| **Installer** | `core.installer` | 处理 install/uninstall 意图 | `fs.write` 到 `~/.startup/skills/`，`db.write` 到 SkillRegistry |
| **Registry** | `core.registry` | 管理本地 Skill 索引与 Hub 查询 | `network.hub`，`db.read/write` |
| **Updater** | `core.updater` | 检查版本更新，处理升级策略 | `fs.modify`，`version.check` |

#### 3.2.2 Meta-Installer 执行流程

`core.installer` 作为普通 Skill 运行，但通过高优先级注册到 L5 层：

$$$
用户触发 skill.install
↓
核心会话将请求路由至 core.installer
↓
core.installer 执行：
  1. 解析槽位（skill_name, version, source_hub）
  2. 调用 core.registry.search() 解析模糊名称到精确ID
  3. 下载 manifest.yaml 预览权限需求
  4. 【安全确认】如 Skill 申请高危权限（如 filesystem.write 到系统目录），向用户展示 Capability 清单并二次确认
  5. 解析依赖树（递归调用自身处理依赖安装）
  6. 调用 PackageDownloader 获取 .startup 包
  7. 调用 SignatureVerifier 验证 Ed25519 签名
  8. 解压到 ~/.startup/skills/{skill_id}@{version}/
  9. 写入 SkillDB（SQLite）
  10. 发送 IPC 信号给 SkillRuntime 执行热加载
  11. 更新 L5 Prompt Layer（注入新 Skill 的 INTENTS.md）
  12. 返回结果给用户："已成功安装 weather-query@v2.1.0，现在你可以说'查北京天气'来测试"
$$$

#### 3.2.3 Meta-Skill 的 Prompt 注入

Meta-Skill 也遵循 L5 层规范，但具有**系统级触发优先级**：

$$$yaml
# core.installer 的 INTENTS.md 片段
intents:
  - id: "skill.install"
    description: "安装新 Skill"
    priority: "system"          # 比普通 skill 高优先级
    patterns:
      - "安装{skill}"
      - "添加{skill}功能"
      - "我需要{skill}"
    slots:
      - name: "skill"
        required: true
        resolver: "fuzzy_search"  # 使用 Registry 模糊匹配
$$$

### 3.3 SkillHub 与分发协议

  - name: "local"
    endpoint: "file:///var/lib/startup/hub"

### 3.4 动态加载与生命周期通知

#### 3.4.1 安装后即时激活

区别于传统重启加载，v1.3 实现**零 downtime 扩展**：

$$$
core.installer 完成文件部署
↓
调用 SkillRuntime.load_skill(skill_id, options: { activate: true })
↓
SkillRuntime:
  1. 创建新的 Sandbox VM
  2. 执行 Skill 的 onInstall() 钩子（如果有）
  3. 解析 INTENTS.md 注册到 IntentRouter
  4. 解析 PROMPT.md 片段，通知 PromptAssembler 更新 L5 层
  5. 向 SessionManager 推送 "skill_installed" 事件
↓
当前活跃会话收到上下文更新通知（增量更新）
↓
用户可立即使用新 Skill，无需重新连接
$$$

#### 3.4.2 安装事务与回滚

安装流程具备**原子性**：

$$$
开始事务 TX
  ↓
下载包 → 验证签名 ✓
  ↓
解析依赖 → 发现冲突 ✗
  ↓
触发回滚：
  - 删除已下载的临时文件
  - 释放已获取的依赖锁
  - 向用户报告："安装中止，依赖冲突：Skill A 需要 http-client@2.x，但 Skill B 锁定 http-client@1.x"
$$$

## 4. 非功能需求

### 4.1 安全与权限

- **Meta-Skill 特权隔离**：即使是 `core.installer`，其代码修改也受限于 `~/.startup/` 目录，通过 OS 文件权限强制隔离
- **安装审计日志**：所有 install/uninstall 操作记录到 `~/.startup/logs/audit.log`，包含时间戳、用户ID、SkillID、签名指纹
- **Capability 预览**：安装前必须展示 Skill 申请的权限清单（如"该 Skill 需要访问互联网 api.weather.com 和写入本地缓存"），用户确认后方可继续

### 4.2 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 意图识别延迟 | &lt;100ms | 从用户说完"安装xx"到路由到 core.installer |
| Hub 搜索响应 | &lt;800ms | 官方 Hub 搜索首屏结果返回 |
| 安装事务耗时 | &lt;5s | 单 Skill 无依赖，网络通畅条件下 |
| 热加载延迟 | &lt;300ms | 下载完成到可用的时间 |

### 4.3 兼容性

- **Meta-Skill 不可卸载**：`core.*` 系列的 Skill 禁止通过 `skill.uninstall` 意图卸载，防止系统失去管理能力
- **降级保护**：若新安装 Skill 导致 Core 崩溃，下次启动时自动进入安全模式（不加载用户 Skill，仅保留 Meta-Skill）

#### 5.2.1 IntentRouter 扩展

#### 5.2.2 Meta-Installer 内部结构

$$$typescript
class MetaInstallerSkill {
  // 实现为标准 Skill 接口，但注册为系统级
  id = 'core.installer';
  
  async handle(request: InstallRequest): Promise&lt;InstallResult&gt; {
    // 1. 解析目标
    const target = await this.registry.resolve(request.skill_hint);
    
    // 2. 权限预览（向用户展示）
    if (target.permissions.some(p =&gt; p.risk_level &gt; 'medium')) {
      await this.promptUserForConsent(target.permissions);
    }
    
    // 3. 依赖解析
    const deps = await this.dependencyResolver.resolve(target);
    
    // 4. 事务执行
    const tx = new InstallTransaction();
    try {
      for (const pkg of deps) {
        await this.download(pkg);
        await this.verify(pkg);
        await this.placeInFilesystem(pkg);
      }
      await this.registerInDB(target);
      await this.runtime.activate(target.id);
      tx.commit();
    } catch (e) {
      tx.rollback();
      throw new InstallError(e);
    }
  }
}
$$$

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **Meta-Skill 单点故障** | 极高 | core.installer 采用极简设计，禁止依赖外部 Skill；系统保留底层 `startup skill` CLI 作为逃生舱 |
| **安装过程中断导致脏数据** | 高 | 事务机制 + 临时目录原子移动（mv 操作保证原子性）+ 启动时自动校验修复 |
| **恶意 Skill 伪装成安装器** | 高 | Meta-Skill 固定 ID 为 `core.*`，禁止用户 Skill 使用该命名空间；IntentRouter 硬编码路由规则 |
| **Hub 依赖导致安装失败** | 中 | 本地缓存优先策略；离线模式支持；企业环境允许预同步 Hub 到内网 |
| **权限提升攻击** | 高 | Capability 预览强制展示；高危权限（如 filesystem.system）默认拒绝，需用户显式配置文件覆盖 |

### 9.2 Meta-Skill 安装普通 Skill 的 Capability 申请示例

$$$yaml
# core.installer 的 manifest.yaml（系统内置，不可卸载）
id: "core.installer"
name: "Skill 安装器"
type: "system"                    # 系统级，不受普通 Capability 限制
permissions:
  - id: "fs.write"
    scope: ["~/.startup/skills/*", "~/.startup/db/*"]
  - id: "network.fetch"
    scope: ["https://hub.startup.ai/*", "https://*.github.com/*"]
  - id: "skill.runtime.manage"
    scope: ["load", "unload", "reload"]
