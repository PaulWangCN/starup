# 项目规范

本文档说明 StarUp 项目的目录结构、开发规范和 AI 使用权限。

## 项目概述

StarUp 是一个 AI 助手运行时环境与集成平台，支持：
- 主会话和子代理 (Sub-Agent) 架构
- 六层 Prompt 工程化体系 (v1.1)
- 双层意图识别引擎 (v1.1)
- **Skill 生态系统 (v1.2)**: 开放式 Skill 动态发现、安全安装与热插拔管理
- 多平台连接器（飞书、微信等）

#### v1.2 核心功能模块 (NEW)

##### 1. Skill 安装系统 (core/skills/ + core/install/)

基于 OpenPack 规范的 Skill 生态系统：

- **InstallManager**: 主安装入口，支持多源安装
  - Marketplace 官方市场
  - Git 仓库安装
  - 本地路径安装
  - URL 直链安装

- **SkillRuntime**: Skill 运行时管理
  - VM 实例池管理
  - 热插拔加载/卸载
  - 跨 Skill 通信总线

- **DependencyResolver**: 依赖解析引擎
  - SAT 求解器处理复杂依赖
  - 版本冲突解决
  - 多版本共存支持

- **Sandbox**: 沙箱隔离模型
  - Capability 权限控制
  - VM 隔离（QuickJS/V8）
  - 资源限制强制执行

##### 2. OpenPack 规范支持

Skill 包规范 (manifest.yaml)：
- 标准化的 Skill 打包协议
- 权限声明（Capability 模型）
- 依赖声明与版本管理
- 运行时配置

##### 3. 安全与权限系统

- **Capability 权限模型**: 显式声明 + 动态授权
- **签名验证**: Ed25519 签名 + SHA-256 校验
- **供应链安全**: HTTPS 强制 + 静态代码扫描

## 开发规范

### 代码规范

1. **语言**: TypeScript 5.0+
2. **代码风格**:
   - 使用单引号
   - 缩进 2 空格
   - 分号必需
   - 尾随逗号

3. **文件命名**:
   - 类文件: PascalCase (如 `PromptAssembler.ts`)
   - 工具文件: camelCase (如 `intentUtils.ts`)
   - 类型文件: 使用 `.d.ts` 后缀

4. **注释规范**:
   ```typescript
   /**
    * 函数描述
    * @param param1 参数说明
    * @returns 返回值说明
    */
   ```

### 模块规范

1. **单例模式**: 核心管理器使用单例导出
   ```typescript
   export class XxxManager { ... }
   export const xxxManager = new XxxManager();
   ```

2. **接口定义**: 在 types/index.ts 中集中定义

3. **错误处理**: 使用 try-catch，错误日志使用 `console.error`

4. **v1.2 新增 - Skill 开发规范**:
   ```typescript
   // Skill 主入口结构
   export default Skill.define({
     id: 'com.example.my-skill',
     version: '1.0.0',
     
     tools: [...],      // 工具定义
     intents: [...],    // 意图定义
     hooks: {           // 生命周期钩子
       onInstall: async () => {...},
       onActivate: async () => {...},
       onUninstall: async () => {...},
     }
   });
   ```

### Git 规范

1. **必须使用 git 进行版本控制**
2. 提交信息格式: `[模块] 描述`
   - 示例: `[prompt] 添加六层组装引擎`
   - 示例: `[intent] 实现置信度评估`
   - 示例: `[skill] 实现 InstallManager` (v1.2)
   - 示例: `[install] 添加依赖解析器` (v1.2)

## 管理原则

1. **版本控制**: 必须使用 git 进行 starup 目录的文件管理，完成开发后需要提交代码并编写commit comment
2. **代码清理**: AI 进行编程、生成文件等改动后必须删除失效、无效的代码和文件
3. **虚拟环境**: Python 项目需要创建 .venv 虚拟环境，在虚拟环境中运行
4. **权限分离**:
   - `docs/human/`: AI 只读
   - `docs/ai/`: AI 可读写
   - `topstar/`: AI 可读写
5. **文档更新**: 开发完成后更新 README.md 与 AGENTS.md 文件
6. **Skill 开发**: 遵循 OpenPack 规范，manifest.yaml 必须包含完整元数据和权限声明
