本文档说明 StarUp 项目的目录结构、开发规范和 AI 使用权限。

## 项目概述

StarUp 是一个 AI 助手运行时环境与集成平台，支持：
- 主会话和子代理 (Sub-Agent) 架构
- 六层 Prompt 工程化体系 (v1.1)
- 双层意图识别引擎 (v1.1)
- Skill 插件系统
- 多平台连接器（飞书、微信等）

#### v1.1 核心功能模块

##### 1. Prompt 组装引擎 (core/prompt/)

六层 Prompt 架构实现：
- L1: SOUL.md - 基础身份
- L2: IDENTITY.md - 身份标识
- L3: USER.md - 用户画像
- L4: TOOLS - 工具定义
- L5: SKILLS - 技能清单
- L6: RUNTIME - 运行时上下文

##### 2. 意图识别系统 (core/intent/)

双层意图识别架构：
- **网关层**: 规则匹配，延迟 < 50ms
- **Skill 层**: 语义匹配，支持 INTENT.md

内置六大核心意图：
- `skill_invoke`: 调用特定 Skill
- `memory_query`: 查询历史记忆
- `code_request`: 代码生成/审查
- `chit_chat`: 闲聊对话
- `system_cmd`: 系统命令
- `escalate`: 转人工/复杂任务

##### 3. 上下文增强 (core/session/)

- **Session Snapshot**: 会话快照和恢复
- **Context Carry**: 跨会话意图继承
- **Model Router**: 意图-模型映射配置

## 开发规范

### 代码规范

1. **语言**: TypeScript 5.0+
2. **代码风格**:
   - 使用单引号
   - 缩进 2 空格
   - 分号必需
   - 尾随逗号

3. **文件命名**:
   - 类文件: PascalCase (如 `PromptAssembler.ts`)
   - 工具文件: camelCase (如 `intentUtils.ts`)
   - 类型文件: 使用 `.d.ts` 后缀

4. **注释规范**:
   ```typescript
   /**
    * 函数描述
    * @param param1 参数说明
    * @returns 返回值说明
    */
   ```

### 模块规范

1. **单例模式**: 核心管理器使用单例导出
   ```typescript
   export class XxxManager { ... }
   export const xxxManager = new XxxManager();
   ```

2. **接口定义**: 在 types/index.ts 中集中定义

3. **错误处理**: 使用 try-catch，错误日志使用 `console.error`

### Git 规范

1. **必须使用 git 进行版本控制**
2. 提交信息格式: `[模块] 描述`
   - 示例: `[prompt] 添加六层组装引擎`
   - 示例: `[intent] 实现置信度评估`

## 管理原则

1. **版本控制**: 必须使用 git 进行 starup 目录的文件管理，完成开发后需要提交代码并编写commit comment
2. **代码清理**: AI 进行编程、生成文件等改动后必须删除失效、无效的代码和文件
3. **虚拟环境**: Python 项目需要创建 .venv 虚拟环境，在虚拟环境中运行
4. **权限分离**:
   - `docs/human/`: AI 只读
   - `docs/ai/`: AI 可读写
   - `topstar/`: AI 可读写
5. **文档更新**: 开发完成后更新 README.md 与 AGENTS.md 文件
